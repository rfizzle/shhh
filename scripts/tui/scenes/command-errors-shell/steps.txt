# The row that did not start is a shell this machine cannot execute, and
# only the real runner can report one; no program test fakes it.
#
# A command that never starts because the execution shell is gone. A bash
# whose interpreter is missing is put first on PATH by the reader's own
# command, so the next command has no shell to run in, and the row names that
# category in the outcome field, with the operating system's words and the
# next action beneath it. It is a scene of its own rather than the end of
# command-errors because that one ends with the working directory removed,
# and a command with no directory never gets as far as its shell.
snap 01-start "Some things worth doing first"
keys "!cp ~/spare/bash ~/bin/bash" Enter
snap 02-shell-card "run it once"
keys y
snap 03-shell-replaced "cp ~/spare/bash"
# The reader's own line is never contained, so this is the bare spawn.
keys "!echo hi" Enter
snap 04-echo-card "run it once"
keys y
snap 05-no-execution-shell "did not start · execution shell" "Nothing ran, and nothing will until that shell is back"
# The assistant's command is the one containment wraps where the host has a
# mechanism: the mechanism starts and only its exec of the shell fails, and
# its row names the same category the bare spawn's did. On a host with none
# (the Linux runner has no bubblewrap) it is the bare spawn again. A
# read-only command is waved through, so there is no card before it; the
# snap waits for the answer that follows the row, and the second row is read
# in the cells.
keys "list the files" Enter
snap 06-contained-no-shell "The contained command could not start" "did not start · execution shell · auto-allowed"
keys C-c
snap 07-quit-armed "again quits"
keys C-c
snap 08-exit "that is everything the screen was holding"
