# The start screen's read-only slot offers what the checkout says is next
# (docs/interface/surfaces.md#the-start-screen). The workspace is a clean
# repository on `main` holding a backlog with one ready item, and a branch two
# commits ahead of it with nothing pushed: the branch is the work in hand, so
# its offer takes the first read-only row with `2 commits ahead · not pushed`
# and the ready item the second, which is what the capture is read for. The
# backlog is a store under .shhh/todo (the backlog's own place), committed on
# main so the tree is clean and the dirty-tree offer does not take the row.
#
# The checkout's AGENTS.md, committed beside it, names docs/cache.md, which is
# not there: the line naming what was read into the system prompt says the
# file names one file that is gone. The assessment that count earns ranks
# after the branch and the item, so it takes no row here.
#
# Then the start screen's reading lands
# (docs/capabilities/chat.md#the-start-screen-is-read-for-this-checkout): the
# scripted model holds it four seconds so the first snap reads the fixed rows,
# and its two offers name the branch and the ready item, so each takes the
# row of the thing it names. The second capture is read for the two written
# rows at the slot's price, with the facts, the notes and the approval row as
# the first capture had them.
#
# The identity is repository-local because the pane runs under a home of its
# own, so there is no global one for the commits to find.
