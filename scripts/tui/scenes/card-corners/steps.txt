#   TestProgram_TheQuitChordArmsThenLeaves

# A card landing on top of the input frame, with both shapes on the screen at
# once: the card in its own tone, the frame in the mode's, and the same four
# corners on each (docs/interface/surfaces.md#the-approval-card). The card
# does not take the panel while the draft still holds the keyboard, which is
# what puts the two rectangles a row apart and makes the comparison possible
# at all.
snap 01-start "Some things worth doing first"
keys "write down what we settled on" Enter
snap 02-card "notes.md"
# A card that has just landed holds its keys for a beat, so the typing waits
# for the grace window rather than racing it. The sentence then goes into the
# draft, not into the card — which is the state the frame is drawn live in.
sleep 1
keys "and then check the round limit"
snap 03-draft-keeps-the-keyboard "and then check the round limit" "[ctrl+space/ctrl+y] answer it · other keys type into the draft"
# Handed the keyboard, the card takes the panel and the frame goes with it;
# the same four corners are then the only frame on the screen.
keys C-Space
snap 04-card-holds-the-keyboard "notes.md" "[y] apply the change"
keys y
snap 05-answered "The note is written"
# The sentence typed at the card went with the answer as its note
# (docs/capabilities/approvals-and-safety.md#a-no-can-say-why-and-a-yes-can-say-what-next),
# so the draft is empty and the first cancel arms the quit.
keys C-c
snap 06-quit-armed "again quits"
keys C-c
# The quit offers a handoff over uncommitted work; n declines.
snap 07a-handoff-offer "Write a handoff first?" "Changes are uncommitted.  [y/N]"
keys n
snap 07-exit "that is everything the screen was holding"
